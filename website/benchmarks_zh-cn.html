基准测试

近期记录的 DeepSeek V4.1 Flash 1017、Muse Spark 与 MiniMax-M3.1-Flash 对比，明确工作负载与质量局限，并介绍正确性测试框架。

最新记录的文本推理对比

这里选取五张 A40 上的 DeepSeek V4.1 Flash 1017、十张 A40 上的 Muse Spark与八张 A40 上的 MiniMax-M3.1-Flash结果。每一行都保留模型、量化、放置方式、工作负载与参照模式；不同指标的最佳 TensorSharp 模式不同，不能把这些行合成总分，也不能据此推断其他硬件或模型的加速比。本次文档更新没有重新运行 DeepSeek 与 Muse Spark 的基准；MiniMax-M3.1-Flash 的数据来自 2026-10-24 的运行。

DeepSeek V4.1 Flash 1017：精确与近似 prefill

记录于 2026-10-22–23：五张 NVIDIA A40（每张 46 GB），unsloth/DeepSeek-V4.1-Flash-1017-GGUF，UD-IQ2_XXS、六个分片，Hugging Face 修订 60ad3651。TensorSharp 使用未修改的 ggml da8e2a5 与 --tp 5；参照是 Unsloth llama.cpp be836572 的按层切分，使用它自带的 in-tree ggml。上下文为 32,768 token，并发 1，输出 256 token，贪心采样、关闭思考；预热后运行三次取中位数。

默认 YOCO 重放是近似执行。设 TS_DSV41_YOCO_KEEP=0 使用精确 prefill。记录的 teacher-forced wikitext-2 检查中，困惑度为精确 2.4811 / 默认近似 2.4978 / llama.cpp 2.4697（越低越好）。近似吞吐量必须与这项质量代价一起阅读，不能称为精确执行的加速比。

测试

下方构建与测试命令需要按平台安装的 .NET 10 SDK；运行命令前请先验证安装。

单元测试（xUnit）

InferenceWeb.Tests 测试无需运行服务器的进程内行为：托管量化运算、直接 CUDA 与 MLX 后端内核（在硬件可用时）、分页 KV 调度、批量执行器正确性、各模型批量前向与单序列路径的一致性、MTP / NextN 推测解码正确性、纯 C# DeepSeek V4.1 执行器对独立 PyTorch 参考实现的数值门控、DiffusionGemma 探针、编解码器往返、提示词渲染，以及服务器 CLI 选项构建器。

其中 V4.1 那一项值得展开说。InferenceWeb.Tests.Dsv41CpuExecutorTests 把 DeepSeek4CpuExecutor（--backend cpu 跑 DeepSeek V4.1 Flash 所用的 100% 纯 C# 执行器，不依赖 ggml、不依赖原生库、不依赖 GPU）对齐到独立的 PyTorch 参考实现 eng/dsv41-reference.py，容差 atol=rtol=2e-5，并要求贪心 argmax 完全一致，覆盖一次性 prefill、分块 prefill（块大小 1/3/5/8，逐位置检查）与 reset。有两条注意事项必须一起交代：夹具检查需要 TS_DSV41_FIXTURE_DIR，不可用场景会显式跳过；而 fixture 是刻意做小的 —— 五层、256 隐藏维、16 token 的 F32 合成模型 —— 因此它证明的是与参考实现的架构级一致，而不是真实 246 GiB Q2_K 权重上的 CPU/CUDA 一致性。它是正确性与可移植性路径，而非服务路径，这也是它只出现在这里、不出现在上面任何表格里的原因：--backend cpu 上跑完整 V4.1 权重的吞吐、加载时间与常驻内存都从未测量过。

dotnet test InferenceWeb.Tests/InferenceWeb.Tests.csproj

Pull request 的 CI 在 GitHub 托管的 x64（ubuntu-latest）与 ARM64（ubuntu-24.04-arm）runner 上运行该测试集中与环境无关的那一档：它强制关闭 GPU 原生构建（CUDA、Vulkan 与 cuDNN），固定 TS_TEST_GGML_BACKEND=cpu，先运行不需要 GPU 的 GB10 容器契约检查 eng/tests/gb10-container.py，全程不需要 GPU，也不下载模型。在本地运行同一档：

dotnet test InferenceWeb.Tests/InferenceWeb.Tests.csproj --filter "Category!=Bench&Requires!=Cuda&Requires!=Mlx&Requires!=Models"

服务器集成测试

TensorSharp.Server.Host/testdata/ 中的集成测试覆盖全部三种 API 风格（Web UI SSE、Ollama、OpenAI）、多轮对话、思考模式、工具调用、结构化输出、队列状态兼容、并发请求与中止支持。架构相关功能会自动检测，并在当前模型不支持时跳过。

# 先启动 TensorSharp.Server.Host，然后运行：
python3 TensorSharp.Server.Host/testdata/test_multiturn.py
# 或
bash TensorSharp.Server.Host/testdata/test_multiturn.sh

推理矩阵运行器

TensorSharp.TestMatrix 是更广泛的、由 CLI 驱动的长时段 模型 × 后端 × 功能 × 环境变量 覆盖框架。它发现 GGUF 文件、过滤不可用后端与不支持的提示类型、运行基线加环境变量扫描的各个 cell、为每个 cell 写一份 JSON 结果、生成聚合 Markdown 报告，并与各主机基线对比。

dotnet build TensorSharp.TestMatrix/TensorSharp.TestMatrix.csproj -c Release
dotnet run --project TensorSharp.TestMatrix -c Release -- --dry-run
