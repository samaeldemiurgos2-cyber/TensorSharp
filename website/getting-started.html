Getting started

Get one text reply first: choose an interface and platform → install → download one model → send a prompt → check the result. Add images, video, multiple GPUs or skills after that path works.

1 · Choose your interface

Your goalStart here
Install and chatDesktop install and first chat. Mac/Windows packages include their runtime; skip the source-build steps below.
Use a terminal, browser or compatible HTTP clientContinue with the CLI/server source path below; both use the same GGUF text model.
Embed the engine in C#Get one text run working, then read package boundaries and integration.

Desktop path: choose the Mac Apple Silicon DMG or Windows x64 MSI on the release page, install and open it, then ☰ → Models → Download → Use and send a message. PKG/ZIP alternatives exist; Windows may need WebView2. The built-in catalog starts at 12 GB system RAM and downloads weights separately. Older releases may lack desktop assets; Desktop install and first chat covers package verification and limits.

The CLI/server also have self-contained release archives for Windows/Linux x64 CPU/CUDA and macOS arm64. Packages reflect their own tag, not every current-source feature. The commands below build source; they do not validate downloaded release archives.

2 · Install and match your platform

Source builds need the .NET 10 SDK

PlatformInstall and check
WindowsPowerShell: winget install Microsoft.DotNet.SDK.10.
macOSInstall the .NET 10 SDK from Microsoft: Arm64 for Apple Silicon, x64 for Intel.
LinuxFollow the distribution instructions, configure its package feed and install the .NET 10 SDK (commonly dotnet-sdk-10.0).

Install the full SDK; the .NET Runtime alone cannot build this source. Open a new terminal and confirm a 10.0.x SDK is listed:

dotnet --list-sdks

Choose the backend for this machine

MachineValue to use belowNative source-build prerequisites
Apple Silicon Macggml_metalGit, curl, CMake 3.20+ and Xcode command-line tools.
Windows / Linux + NVIDIAggml_cudaCMake, a C++ toolchain, NVIDIA driver and matching CUDA Toolkit; Windows needs Visual Studio C++ build tools.
Windows / Linux + Vulkan GPUggml_vulkanCMake, C++/Vulkan build tools and a Vulkan 1.3 driver.
CPU, no GPUggml_cpuCMake 3.20+ and a C++ compiler; this is still a native build.

Examples use ggml_cpu; replace the backend with one value from the table. Before a CUDA build set TENSORSHARP_GGML_NATIVE_ENABLE_CUDA=ON; for Vulkan use TENSORSHARP_GGML_NATIVE_ENABLE_VULKAN=ON. In Windows PowerShell the CUDA form is $env:TENSORSHARP_GGML_NATIVE_ENABLE_CUDA="ON"; on macOS/Linux it is export TENSORSHARP_GGML_NATIVE_ENABLE_CUDA=ON. Metal needs no CUDA switch. See the backend and native-build guide for complete installation, automatic Vulkan tooling and MLX prerequisites.

Get the source

git clone https://github.com/zhongkaifu/TensorSharp.git
cd TensorSharp

Run the application project below; its first invocation restores and builds it. You do not need to build the whole solution and desktop apps first. Git, curl and network access fetch source, dependencies and the model; the first native build fetches upstream ggml.

3 · Download one text model

This example uses the public Gemma 4 E4B Q8_0, a 7.48 GiB file. Disk size is not the runtime memory requirement: leave room for KV cache and execution. A smaller Q4_K_M is in the same repository; check the Gemma 4 model card and other model downloads before changing model or quantization. Text input needs no mmproj.

Windows PowerShell download command 
curl.exe --create-dirs --fail -L "https://huggingface.co/ggml-org/gemma-4-E4B-it-GGUF/resolve/main/gemma-4-E4B-it-Q8_0.gguf?download=true" -o models/gemma-4-E4B-it-Q8_0.gguf
macOS / Linux download command 
curl --create-dirs --fail -L "https://huggingface.co/ggml-org/gemma-4-E4B-it-GGUF/resolve/main/gemma-4-E4B-it-Q8_0.gguf?download=true" -o models/gemma-4-E4B-it-Q8_0.gguf

4 · Get your first text reply

Run from the repository root and replace ggml_cpu using the platform table. A one-shot CLI text prompt comes from a file via --input; --prompt belongs to image/video generation. This example uses greedy sampling and at most 32 output tokens. The first native build can take several minutes.

Terminal: Windows PowerShell 
'What is 2+2? Reply with only the number.' | Set-Content -Encoding utf8 prompt.txt
dotnet run --project TensorSharp.Cli -c Release -p:TensorSharpSkipMlxNative=true -- --model models/gemma-4-E4B-it-Q8_0.gguf --input prompt.txt --backend ggml_cpu --temperature 0 --max-tokens 32
Terminal: macOS / Linux 
printf '%s\n' 'What is 2+2? Reply with only the number.' > prompt.txt
dotnet run --project TensorSharp.Cli -c Release -p:TensorSharpSkipMlxNative=true -- --model models/gemma-4-E4B-it-Q8_0.gguf --input prompt.txt --backend ggml_cpu --temperature 0 --max-tokens 32

Prefer a browser or HTTP? Start the server with the same model and selected backend instead, and leave this terminal running:

dotnet run --project TensorSharp.Server.Host -c Release -p:TensorSharpSkipMlxNative=true -- --model models/gemma-4-E4B-it-Q8_0.gguf --backend ggml_cpu --host 127.0.0.1 --port 8080 --max-tokens 32

Open http://127.0.0.1:8080/ and send the same arithmetic prompt. These examples explicitly use loopback and port 8080; the actual default is 0.0.0.0:5000, and macOS commonly reserves 5000 for AirPlay. The server has no built-in authentication or TLS; remote deployments need their own authenticated HTTPS boundary.

5 · Verify this path

CheckExpected result
CLI or browser replyNonempty assistant text; the arithmetic example should answer 4. Log messages alone are not a model reply.
Process and errorsThe CLI exits normally; the server stays running. Resolve download, build or model-load errors at that stage.
Server livenessGET /health returns TensorSharp.Server is running. This checks liveness, not model readiness or quality.
Model and APIGET /v1/models lists the configured model ID. For a direct request, use the JSON below.

Check from another terminal; in Windows PowerShell use curl.exe instead of curl:

curl --fail http://127.0.0.1:8080/health
curl --fail http://127.0.0.1:8080/v1/models

Save this as request.json; if the model ID differs, use the ID returned by /v1/models:

{
  "model": "gemma-4-E4B-it-Q8_0",
  "messages": [
    {
      "role": "user",
      "content": "What is 2+2? Reply with only the number."
    }
  ],
  "temperature": 0,
  "max_tokens": 32,
  "stream": false
}
curl --fail http://127.0.0.1:8080/v1/chat/completions -H "Content-Type: application/json" --data-binary "@request.json"

Check that choices[0].message.content contains text. With the Web UI available, / opens chat; with --no-webui or no Web UI files, / returns liveness text. The stable liveness route is /health in either case. For terminal conversations use CLI --interactive; see the CLI reference and HTTP API examples for full formats.

If a step fails

SymptomNext check
No 10.0.x SDKInstall the SDK and open a new terminal; the runtime alone is insufficient.
CMake, compiler or GPU library errorCheck the backend and native-build guide; when native builds are unavailable, try the managed CLI path below.
Model path or memory errorConfirm a complete download, matching filename and room beyond weight size; choose a supported quantization.
Server cannot listenKeep --host 127.0.0.1, choose a free --port, and update request URLs together.
Liveness works but no model replyRead load logs and /v1/models, then check the request against HTTP API examples. Liveness is not an inference check.
No native toolchain: managed CPU CLI path

cpu is pure C#, distinct from native ggml_cpu. It emphasizes portability and debugging; check model/feature coverage. Explicitly skip both native builds:

dotnet run --project TensorSharp.Cli -c Release -p:TensorSharpSkipGgmlNative=true -p:TensorSharpSkipMlxNative=true -- --model models/gemma-4-E4B-it-Q8_0.gguf --input prompt.txt --backend cpu --temperature 0 --max-tokens 32

Advanced setups and references

  • Desktop source builds: TensorAgent build and validation retains MAUI workloads, platform app heads, TensorSharpSkipTensorAgentApp and missing-prerequisite skip behavior. Building a test project does not run its tests.
  • Embeddings: the separate service guide retains MiniLM/Snowflake downloads, --embeddings, managed/native backends and /v1/embeddings / /api/embed requests. Run chat and embeddings on different ports.
  • Knowledge: the knowledge guide retains TS_KNOWLEDGE_DIRECTORY, knowledgeCollections, BM25/optional embeddings, Reindex and media-extraction limits. Uploading still requires selecting “Use in this chat”.
  • Multimodal input: the Gemma 4 model card retains matching projector filenames and explicit --mmproj; the server does not auto-detect a projector. The MiniMax-H3 guide retains the ~46 GB config, 1.38 GB Turbo factors, sampling constraints and TS_VIDEO_TOKENIZER.
  • DGX Spark / GB10: the experimental CUDA 13 / Linux ARM64 build targets a single GB10, not x64 CUDA archives or generic ARM64 GPUs. Its historical hardware check predates upstream reintegration; hosted CI checks CPU/archive paths.
Compatibility notes for existing advanced deployments

For native ggml source builds, TENSORSHARP_GGML_NO_UPDATE=1 skips subsequent network updates. The cache guide retains default Radix behavior, TS_SCHED_PREFIX_CACHE=0, --no-prefix-cache and server disk checkpoints. The earlier guide's environment-specific Ubuntu settings remain below for matching CUDA/package-source environments; they are not part of the normal first run:

# RunPod Ubuntu 24.04 images using this CUDA compatibility directory:
export LD_LIBRARY_PATH=/usr/local/cuda-12.6/compat:$LD_LIBRARY_PATH
# Older Ubuntu releases needing the .NET backports package source:
add-apt-repository ppa:dotnet/backports
apt update && apt install dotnet-sdk-10.0
